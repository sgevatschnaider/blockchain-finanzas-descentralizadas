Esta guía fue preparada para que el estudiante pueda estudiar los contenidos centrales de la materia con un criterio integrado. Cada pregunta incluye una respuesta central, un desarrollo conceptual, una aplicación, puntos clave y un error frecuente. El objetivo no es memorizar frases, sino comprender mecanismos, relaciones y límites.

El examen se elaborará sobre los conceptos desarrollados aquí. Una pregunta puede aparecer formulada de otra manera, mediante una comparación o un pequeño caso, pero no se busca sorprender con contenidos conceptuales ajenos a la guía. Quien sea capaz de explicar estas preguntas con palabras propias y resolver sus ejemplos debe llegar conceptualmente preparado para la evaluación.

Método recomendado: intentar responder primero sin mirar, luego comparar la explicación propia con la respuesta y, finalmente, poder reconstruir el concepto en voz alta en dos o tres minutos. Conviene estudiar relaciones causales: qué problema resuelve cada mecanismo, cómo funciona, qué supuesto introduce y qué no puede resolver.

Síntesis

Cómo conectar toda la materia

La materia no debe estudiarse como una lista de términos. Puede reconstruirse como una cadena de problemas: coordinación -> descentralización -> criptografía -> consenso -> estado -> transacciones -> smart contracts -> oráculos -> Bitcoin/Ethereum -> escalabilidad -> Lightning/Rollups -> ZKP -> DeFi -> IoT/ML -> aplicaciones reales.

Bitcoin responde, entre otras cuestiones, cómo transferir valor digital evitando el doble gasto sin una autoridad central única. Ethereum amplía la pregunta hacia un estado programable compartido. Los smart contracts automatizan reglas; los oráculos conectan esas reglas con información externa; Lightning y los rollups desplazan actividad a capas superiores; las ZKP permiten verificar propiedades o cálculos sin revelar o reejecutar todo; IoT y Machine Learning introducen el desafío de convertir datos del mundo físico en señales confiables y decisiones controladas.

El criterio integrador más importante es preguntar siempre qué problema se intenta resolver, qué supuestos de confianza aparecen y qué parte de la solución pertenece realmente a blockchain. Una arquitectura correcta no es la que usa más tecnología, sino la que asigna a cada componente la función para la cual resulta más adecuado.

Antes del examen

Checklist de dominio

  • Puedo explicar con palabras propias la diferencia entre integridad, autenticidad y veracidad.
  • Puedo construir conceptualmente una transacción UTXO con inputs, outputs, cambio y fee.
  • Puedo explicar PoW, target, chainwork, reorgs y confirmaciones sin usar definiciones circulares.
  • Puedo describir una transacción Ethereum, el papel del gas, la EVM y el receipt.
  • Puedo diferenciar fork choice, finality, slashing e inactivity leak.
  • Puedo explicar por qué un token técnico no equivale automáticamente a un derecho jurídico.
  • Puedo dibujar una arquitectura IoT -> almacenamiento off-chain -> hash/CID -> anchor on-chain.
  • Puedo modelar Lightning como grafo con capacidad y costo y explicar Dijkstra.
  • Puedo diferenciar ZKP, ZK-Rollup, validity y data availability.
  • Puedo explicar cómo un AMM produce slippage y por qué el orden genera MEV.
  • Puedo distinguir una anomalía de ML de una falla causal y explicar las limitaciones de Isolation Forest.
  • Puedo justificar cuándo NO usaría blockchain.
