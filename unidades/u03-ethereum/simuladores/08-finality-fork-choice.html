¿Qué rama es la cabeza y cuándo un checkpoint queda finalizado?

Generá una bifurcación, mové el peso de las latest attestations entre dos ramas y observá cómo LMD-GHOST cambia la head. Después acumulá votos de checkpoint para visualizar justification y una versión pedagógica de Casper FFG finalization.

Objetivo de aprendizajeDistinguir dos tareas: fork choice decide qué bloque es la cabeza ahora; finality da seguridad económica a checkpoints anteriores. Son mecanismos relacionados, pero no equivalentes.
Preparado
Modelo pedagógico: reproduce la lógica conceptual de latest-message-driven subtree weight y checkpoints con umbral de ⅔. No implementa todos los detalles del consenso de producción.

Precisiones técnicas

qué enseña el modelo
Fork choice
Busca una cabeza de cadena operativa usando attestations recientes. Puede cambiar cuando cambia el peso observado.
Justification
Un checkpoint recibe suficiente respaldo de votos FFG desde un checkpoint fuente justificado.
Finalization
Agrega seguridad económica a checkpoints anteriores. El laboratorio usa una regla simplificada de checkpoints consecutivos justificados.
No implementa
Toda la estructura de votos source/target/head, balances efectivos, proposer boost, equivocaciones/slashing ni casos completos de reorg.
