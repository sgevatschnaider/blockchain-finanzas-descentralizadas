Del código Solidity a un contrato con estado y eventos

Recorré el ciclo completo: source code, compilación didáctica, creation bytecode, transacción de deploy, cálculo de dirección, llamada a una función, cambio de storage, emisión de event logs y receipt.

Objetivo de aprendizajeSeparar claramente tres cosas distintas: el código fuente que escribe el desarrollador, el bytecode que ejecuta la EVM y el estado persistente que vive en la cuenta del contrato.

Lectura conceptual

tres capas distintas
Source
Es legible por humanos y sirve para desarrollar/auditar. La EVM no ejecuta Solidity directamente.
Code
El runtime bytecode queda asociado a la cuenta del contrato y es lo que ejecuta la EVM.
State
El storage persiste entre llamadas y cambia sólo cuando una ejecución válida modifica sus slots.
